# vte.cx 設定ファイルの反映ルール

このプロジェクトでは、vte.cx の設定ファイルを変更した場合、必要に応じて vte.cx サービスへアップロードする必要があります。

主な対象は次のとおりです。

- `template.xml`
- `folderacls.json`
- その他、既存の開発手順で vte.cx への反映が必要とされている設定ファイル

ただし、`properties.xml` は例外です。

`properties.xml` にはクレデンシャルや機密情報が含まれるため、AIエージェント、Work、CI、その他の自動処理からアップロードしてはいけません。

`properties.xml` は利用者が手元に保持しているファイルを、必要に応じて手動で vte.cx へアップロードしてください。

## vte.cx へのログイン

vte.cx へのログインには `@vtecx/vtecxutil` を使用します。

ログインが必要な場合は、プロジェクトの既存スクリプトを使用します。

`pnpm run login`

### `pnpm run login` は対話式コマンド

`pnpm run login` は対話式コマンドであり、実行するとユーザIDとパスワードの入力を求めるプロンプトが表示されます。

AIエージェント、Work、Claude Code などがこのコマンドを実行する場合は、ログインコマンド自体は開始して構いません。

ただし、ユーザIDやパスワードの入力が必要になった時点で、利用者へ入力を求めてください。

エージェントが以下を行ってはいけません。

- ユーザIDを推測する
- パスワードを推測する
- 認証情報を自動生成する
- 認証情報をソースコードへ保存する
- 認証情報を `.env` へ保存する
- 認証情報をドキュメントへ保存する
- 認証情報をログへ出力する
- 認証情報を Issue / Pull Request へ記載する
- 認証情報を作業報告へ含める

ログイン時の認証情報は、必要なタイミングで利用者が直接入力することを基本とします。

### ログイン状態の保存

ログインに成功すると、ホームディレクトリの `~/.confy` に以下の情報が保存されます。

- vte.cx のサービス名
- アクセストークン
- デフォルトサービス

一度ログインした後は、別の vte.cx サービスへログインしない限り、デフォルトサービスはそのサービスに固定されます。

したがって、設定ファイルをアップロードするたびに `pnpm run login` を実行する必要はありません。

`~/.confy` に正しいサービスのログイン情報が残っている場合は、そのログイン状態を再利用してください。

### Work やクラウド実行環境での注意

Work などのクラウド実行環境では、実行環境が再作成された場合に `~/.confy` が保持されない可能性があります。

その場合は、再度 `pnpm run login` が必要です。

一方、Claude Code など、同じローカル環境を継続して利用する場合は、通常 `~/.confy` が残るため、毎回ログインする必要はありません。

ログイン済みかどうかは推測せず、実際に `~/.confy` を確認してください。

## アップロード前の確認

vte.cx へ設定ファイルをアップロードする前に、必ず現在のデフォルトサービスを確認してください。

`~/.confy` に保存されているデフォルトサービスと、今回反映する対象サービスが一致していることを確認します。

一致していない場合は、そのままアップロードしてはいけません。

必要に応じて `pnpm run login` を実行し、正しいサービスへ切り替えてください。

対象サービスが判断できない場合は、アップロードを実行せず利用者へ確認してください。

## 認証情報の扱い

ユーザID、パスワード、アクセストークン、APIキー、秘密鍵、その他のクレデンシャルを以下へ保存してはいけません。

- Git リポジトリ
- ソースコード
- `AGENTS.md`
- README
- その他のドキュメント
- `.env` など、リポジトリへコミットされる可能性があるファイル
- ログ
- 作業報告
- Issue / Pull Request の本文やコメント

ログイン時に認証情報の入力が必要になった場合は、利用者に入力を求めてください。

認証情報を推測したり、自動生成したりしてはいけません。

## properties.xml の扱い

`properties.xml` は通常の設定ファイルとは異なり、クレデンシャルや機密情報を含むため、自動反映の対象外とします。

以下を厳守してください。

- `properties.xml` を AIエージェントや Work からアップロードしない
- `properties.xml` を CI/CD からアップロードしない
- `properties.xml` を Git リポジトリへ追加しない
- `properties.xml` の内容をログや作業報告へ出力しない
- `properties.xml` の内容を別ファイルへ転記しない
- `properties.xml` の内容を自動生成・推測しない
- `properties.xml` の内容を Issue や Pull Request へ貼り付けない
- `properties.xml` の内容を AI への指示文へ含めない

`properties.xml` の反映が必要な場合は、利用者が手元に保持している正しいファイルを使用して、手動で vte.cx へアップロードしてください。

AIエージェントや Work は、`properties.xml` の変更や反映が必要と思われる場合でも、自動アップロードせず、利用者へ手動対応が必要であることを通知してください。

## vte.cx への設定ファイルアップロード

vte.cx への設定ファイル反映には、既存のプロジェクトコマンドを使用してください。

独自に API 呼び出しを実装したり、別のアップロード方法を作成したりしてはいけません。

### template.xml のアップロード

`template.xml` をアップロードする場合は、次のコマンドを使用します。

`pnpm upload:template`

`pnpm upload:template` が正常に完了した後は、必ず次のコマンドを実行してください。

`pnpm download:typings`

`pnpm download:typings` は、vte.cx 側へ反映された最新のテンプレート定義に基づく型情報を取得するために実行します。

したがって、`template.xml` の反映は次の2つを1セットとして扱ってください。

1. `pnpm upload:template`
2. `pnpm download:typings`

`pnpm upload:template` が失敗した場合は、`pnpm download:typings` を実行しないでください。

### folderacls.json のアップロード

`folderacls.json` をアップロードする場合は、次のコマンドを使用します。

`pnpm upload:folderacls`

これらの既存コマンドを優先し、独自のアップロードスクリプトや代替手段を作成しないでください。

## 作業前に確認するもの

設定ファイルの反映作業を行う前に、必要に応じて以下を確認してください。

- `package.json`
- `pnpm-lock.yaml`
- `@vtecx/vtecxutil` の利用方法
- `pnpm run login` の定義
- `pnpm upload:template` の定義
- `pnpm download:typings` の定義
- `pnpm upload:folderacls` の定義
- `template.xml` の配置場所
- `folderacls.json` の配置場所
- README や開発ドキュメント
- Git の差分

既存の仕組みや手順がある場合は、それを優先してください。

今回の設定ファイル反映のためだけに不要なコード変更を行ってはいけません。

## Git 差分の確認

設定ファイルをアップロードする前に Git の差分を確認してください。

今回変更されたファイルだけを反映することを基本とします。

特に次のファイルを確認してください。

- `template.xml`
- `folderacls.json`

変更内容に応じて、以下のコマンドを使用してください。

- `template.xml` が変更されている場合:
  1. `pnpm upload:template`
  2. 成功後に `pnpm download:typings`
- `folderacls.json` が変更されている場合:
  - `pnpm upload:folderacls`

両方が変更されている場合は、それぞれの反映処理を実行してください。

変更されていない設定ファイルを理由なく再アップロードしないでください。

また、今回の作業と無関係な差分が含まれている場合は、そのまま反映しないでください。

`properties.xml` が差分や作業対象として見つかった場合でも、自動アップロード対象には含めないでください。

## template.xml の変更ルール

`template.xml` を変更する場合は、既存の vte.cx スキーマ運用ルールを守ってください。

特に重要なルールとして、既存項目の途中へ新しい項目を追加してはいけません。

新しい項目を追加する場合は、既存項目の順序を維持し、適切な末尾位置へ追加してください。

また、次の変更を理由なく行わないでください。

- 既存項目の並べ替え
- 既存項目の削除
- 今回の変更と無関係な項目の修正
- 意図しない型の変更
- 意図しない属性の変更
- 既存定義の大規模な整形

アップロード前に必ず差分を確認し、意図しない変更が含まれていないことを確認してください。

## template.xml 反映後の型情報同期

`template.xml` を vte.cx へアップロードした後は、必ず型情報を再取得してください。

実行順序は固定です。

1. `pnpm upload:template`
2. `pnpm download:typings`

`pnpm upload:template` の成功を確認してから `pnpm download:typings` を実行してください。

型情報の取得後は、Git の差分を確認し、型定義ファイルに意図した変更が反映されていることを確認してください。

型情報の更新によって新しい差分が発生した場合は、その差分を今回の `template.xml` 変更に伴う生成物として扱ってください。

`pnpm download:typings` が失敗した場合は、成功扱いにせず、エラー内容を確認して利用者へ報告してください。

## folderacls.json の変更ルール

`folderacls.json` を変更する場合は、次の内容を確認してください。

- 対象パス
- 権限範囲
- role
- user
- group
- 既存ユーザーへの影響
- 既存権限への影響

今回の変更と無関係な権限設定を変更してはいけません。

権限変更は影響範囲が大きいため、意図が明確でない場合は反映前に利用者へ確認してください。

## 本番サービスへの反映

本番サービスへ設定ファイルをアップロードする場合は、実行直前に対象サービスを再確認してください。

AIエージェントや Work から実行する場合は、本番反映前に利用者の確認を求めてください。

確認なしに本番サービスへアップロードしてはいけません。

対象サービスが不明な状態で本番反映を行ってはいけません。

`properties.xml` は本番・開発・検証のいずれであっても、自動アップロードしてはいけません。

## アップロード実行時のルール

### template.xml

`template.xml` が変更されていることを確認し、対象サービスが正しいことを確認したうえで、

`pnpm upload:template`

を実行してください。

正常終了した場合は、続けて必ず、

`pnpm download:typings`

を実行してください。

`pnpm upload:template` が失敗した場合は、`pnpm download:typings` を実行しないでください。

### folderacls.json

`folderacls.json` が変更されていることを確認し、対象サービスが正しいことを確認したうえで、

`pnpm upload:folderacls`

を実行してください。

アップロードコマンドを実行する前に、現在の `~/.confy` のデフォルトサービスが正しいことを確認してください。

## アップロード後の確認

アップロード後は、各コマンドの終了結果を確認してください。

確認する内容は次のとおりです。

- 対象サービス
- アップロードしたファイル
- 実行したコマンド
- 終了コード
- エラーの有無
- vte.cx 側への反映結果
- `template.xml` を反映した場合は `pnpm download:typings` の実行結果
- 型定義ファイルの差分

可能であれば、既存の確認方法を使用して、vte.cx 側へ正しく反映されたことも確認してください。

アップロードに失敗した場合は、同じ処理を無条件に繰り返してはいけません。

まずエラー内容を確認し、原因を整理してください。

必要な場合は利用者へ確認してください。

## エージェントが作業する場合

AIエージェントや Work、Claude Code がこの作業を行う場合は、次の順序を守ってください。

1. Git の差分を確認する
2. `template.xml` に変更があるか確認する
3. `folderacls.json` に変更があるか確認する
4. `properties.xml` は自動アップロード対象から除外する
5. `~/.confy` のデフォルトサービスを確認する
6. 今回の対象サービスと一致していることを確認する
7. 対象サービスが異なる場合や未ログインの場合のみ `pnpm run login` を実行する
8. `pnpm run login` のプロンプトでユーザIDやパスワードが必要になった場合は、利用者へ入力を求める
9. `template.xml` が変更されている場合は `pnpm upload:template` を実行する
10. `pnpm upload:template` が成功した場合は、必ず `pnpm download:typings` を実行する
11. `pnpm download:typings` 後に型定義ファイルの差分を確認する
12. `folderacls.json` が変更されている場合は `pnpm upload:folderacls` を実行する
13. 各コマンドの終了結果を確認する
14. 必要に応じて vte.cx 側への反映結果を確認する
15. 実行結果を利用者へ報告する

対象サービスが一致しない場合や、ログイン情報が不足している場合は、そのまま処理を進めず利用者へ確認してください。

`properties.xml` の反映が必要な場合は、自動アップロードせず、利用者へ手動アップロードが必要であることを報告してください。

## エージェントが行ってはいけないこと

AIエージェントや Work、Claude Code は、以下を行ってはいけません。

- `properties.xml` をアップロードする
- `properties.xml` の内容を表示する
- クレデンシャルをリポジトリへ保存する
- クレデンシャルをログへ出力する
- `pnpm run login` の認証情報を推測する
- `pnpm run login` の認証情報を自動生成する
- 対象サービスを確認せずにアップロードする
- `template.xml` の既存項目の途中へ新規項目を追加する
- `folderacls.json` の権限を意図なく変更する
- 独自の vte.cx アップロードAPIを実装する
- `pnpm upload:template` の代替処理を勝手に作る
- `pnpm upload:folderacls` の代替処理を勝手に作る
- `template.xml` をアップロードした後に `pnpm download:typings` を省略する
- `pnpm upload:template` が失敗しているのに `pnpm download:typings` を実行する
- 失敗したアップロードを原因確認なしに繰り返す
- 本番環境へ確認なしに反映する

## 作業完了時の報告

作業完了後は、以下を簡潔に報告してください。

- 使用した vte.cx サービス名
- `pnpm run login` を実行したか
- ログイン時に利用者入力が必要だったか
- `template.xml` をアップロードしたか
- `pnpm download:typings` を実行したか
- 型情報の更新結果
- `folderacls.json` をアップロードしたか
- 実行したコマンド
- 各コマンドの結果
- エラーの有無
- `properties.xml` の手動対応が必要か
- その他、利用者による確認が必要な事項

認証情報やアクセストークンそのものは報告に含めないでください。

## 基本方針

vte.cx の設定反映では、利便性よりも安全性と同期の正確性を優先します。

特に次の点を守ってください。

- 誤った vte.cx サービスへのアップロードを防ぐ
- `~/.confy` のデフォルトサービスを必ず確認する
- `pnpm run login` は対話式コマンドとして扱う
- ログイン時のユーザID・パスワード入力は利用者に求める
- `template.xml` は `pnpm upload:template` で反映する
- `template.xml` 反映後は必ず `pnpm download:typings` で型情報を同期する
- `folderacls.json` は `pnpm upload:folderacls` で反映する
- `properties.xml` は自動アップロードしない
- `properties.xml` は利用者が手元のファイルを手動でアップロードする
- クレデンシャルを Git やログへ残さない
- 既存の反映手順を尊重する
- `template.xml` の項目を途中追加しない

現在ログインしているサービスや設定内容を、推測だけで判断しないでください。
